open-geo — a GEO visibility tracker that reads the rendered AI answer

open-geo is a GEO (generative engine optimization) visibility tracker: it measures whether your brand shows up in AI answers by reading the rendered answer a logged-in user actually sees. Capture runs through an agent in a real, logged-in browser, not the engine's API and not a headless scrape, because those do not match the answer a person is shown. It covers Google AI Overview, ChatGPT, Claude, Gemini, Yandex Alice and DeepSeek, and reports an honest funnel that says when a run cannot be trusted instead of guessing.

How it works

  1. A readiness audit runs first. A deterministic, non-LLM check of whether an AI engine can read the target domain at all: HTTPS and reachability, a homepage that returns 200, robots.txt not blocking the engine's search crawler, content present in raw HTML. Hard blockers stop the run before a single token is spent; everything else is advisory and ships with a concrete fix.
  2. Capture reads the rendered answer. For each query, an agent follows a per-engine playbook in a visible, logged-in Chrome, expands the sources panel and the inline citation chips, normalizes domains, and emits one validated record.
  3. Scoring is plain arithmetic. Records land in a local SQLite database and are scored per lens (general, branded, comparative) plus an aggregate row. Every number traces to one formula in the published contract.
  4. You get a dashboard and a PDF. Both are local, in four languages, built from the same scored run, with run-over-run deltas from your own history. The PDF is a standalone document rather than a summary of the dashboard: every query grouped by how the brand ended up in the answer, a separate list of the answers the brand was absent from, the readiness audit with its fixes, and a glossary of every formula.

What it measures

The counts nest, so each step is a subset of the one before it: cited ≤ in sources ≤ answered ≤ queries. A model can only cite what it retrieved, so citations are a subset of sources. The denominator for visibility is answer-present queries: you can only be visible where an answer actually rendered.

MetricMeaningDirection
Answer coverageShare of queries that produced an AI answer at allhigher is better
Visibility in sourcesOf answered queries, share where your target made it into the relied-on sourceshigher is better
Visibility in citationsOf answered queries, share where your target is cited in the answerhigher is better
Average source positionAverage best rank among sources, over queries where it appearslower is better
Average citation positionAverage best rank among citations, over queries where it is citedlower is better
Relative citationSource-to-citation conversion: of queries where you were retrieved, the share actually citedhigher is better
Brand mention rateShare of answers whose text names the brand, linked or not — an adjacent axis, not a funnel stagehigher is better

There is deliberately no composite index, no share-of-voice index and no numeric sentiment. Sentiment stays a short qualitative note, and competitive context is a top-domains leaderboard of plain frequencies and positions.

How open-geo compares

Three different shapes solve "am I visible in AI answers?", and they are not interchangeable. This is about what each shape is built for.

ScaleTens to low hundreds of queries per runThousands of prompts, hands-offBounded by budget and rate limits
Where results liveLocal SQLite history, local dashboard and PDFThe vendor's cloudWherever you put them
When data is shakyA grounded-answer gate and a nested funnel; a run is flagged, never guessedVendor-definedYours to design

The trade-off is deliberate: fidelity over volume. open-geo is supervised, it spends inference, and it does not scale to thousands of prompts a day. In exchange, every number traces to an answer a logged-in person could actually have been shown. If you need continuous coverage across a large prompt set, a hosted monitor is the right shape.

Get started

Clone the repository and ask Claude to set it up, or install it as a Claude Code plugin:

/plugin marketplace add Pupok462/open-geo
/plugin install open-geo@open-geo-marketplace

Then run a capture against your own question set:

/open-geo questions.csv google example.com --brand "Example" --n-worker 3 --output both

Plugin skills are namespaced, so the plugin-installed command is /open-geo:open-geo. The one thing that cannot be automated for you: connecting the Claude-in-Chrome extension and logging the browser in to the market you want to track.

Frequently asked questions

What is GEO (generative engine optimization)?

GEO is the practice of getting a brand surfaced and cited inside AI-generated answers, rather than ranked in a list of links. It is also called AEO (answer engine optimization). The measurement problem differs from SEO: there is no rank position to read, so what you track is whether an answer retrieved you, whether it cited you, and where in the answer you landed.

Is there a GEO or AI-visibility tracker for Claude Code?

Yes — open-geo is one. It installs as a Claude Code skill and runs as a single command, driving your logged-in Chrome through the Claude-in-Chrome extension.

Which AI engines can open-geo track?

Seven today: Google AI Overview, ChatGPT with web search, Claude with web search, Google Gemini, Yandex Alice / Нейро, DeepSeek with web search, and Perplexity — each one live-validated against the real interface. Each engine is a natural-language playbook, so adding one means writing a markdown file rather than a parser.

Can I track brand visibility in Yandex Alice or DeepSeek?

Yes, both are supported engines. They matter because Russian- and Chinese-market answer engines are commonly left out of Western tooling, and each has quirks the playbook handles: Yandex mixes paid promo cards in with sources, which open-geo deliberately keeps out of sources and citations, and DeepSeek numbers its retrieved set the way Perplexity does.

Does open-geo use the engine's API or the real UI?

The real UI. An agent drives a visible, logged-in Chrome and reads the answer as it was rendered to a person: the sources panel, the inline citation chips, the answer text. API and headless reads do not match what a logged-in user is actually shown, so they measure a surface nobody sees.

Is open-geo an audit or 24/7 monitoring?

An audit you run on demand. A run is supervised, spends inference, and measures the questions you chose. To repeat it, wrap the command in Claude Code's /loop, or use --repeat to capture the same set several times and read the min–max spread.

How is open-geo different from a hosted AI-visibility monitoring service?

It trades volume for fidelity: it reads the rendered answer in your own logged-in browser, keeps history locally, and flags a run it cannot vouch for instead of guessing — at the cost of scale and of being hands-on. A hosted monitor is the better fit when you need thousands of prompts tracked continuously without supervision.

Can I track a GitHub repo or a URL prefix instead of a whole domain?

Yes. The target accepts a domain such as example.com or a URL prefix such as github.com/user/repo, so you can measure a single repo, a docs section or a subfolder. Prefix matching is conservative: a link that only names the domain is not counted as a match when the target has a path.

Do I need any paid API keys to run open-geo?

No external data API and no paid keys. You need Claude Code, the Claude-in-Chrome extension connected, and a browser already logged in to the engine and market you want to track.

Is open-geo free and open source?

Yes — MIT-licensed, with no data API or paid key in the loop. Running it does spend your own Claude Code inference.

About

open-geo is an open-source project built around one insight: measuring AI visibility through an API or a headless browser does not match the answer a logged-in person is actually shown, so the measurement has to happen on the real, rendered surface. The full methodology, the capture playbooks and the metric contract are public and auditable in the repository.
